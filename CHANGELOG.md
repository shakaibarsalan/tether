# Changelog

## 0.3.5 (2026-11-25)

After updating: restart the broker (`scripts/broker-setup.ps1 -Restart` or `scripts/broker-setup.sh --restart`; Chrome asks "Allow?" once). The extension is unchanged (1.1.2). If you loaded it from a folder other than this copy's `extension` folder, add its ID from `chrome://extensions` to `"extensionIds"` in `~/.tether/config.json`.

- **Claude's tabs in a profile without your logins or the extension:** a chat's first tab opened in Chrome's default profile, which needn't be the one you use: a new window, not signed in, the old orange frame instead of the extension's look, and Chrome brought to the front. Now the broker opens Claude's tabs in the profile where the Tether extension is loaded. It knows the extension by its ID (Chrome makes an unpacked extension's ID from its folder's path; the broker works it out for its own `extension` folder, and takes more from `"extensionIds"` in `~/.tether/config.json`), and finds its profile when the extension's service worker runs there or the extension answers in a tab. A chat whose tabs are in a profile without the extension moves to that one for its next tab. With no such profile, nothing changes. `broker.log` says which profile a chat's tabs go to.
- **The same site opened again and again:** which tabs a chat opened was kept only in the broker's memory, so after a broker restart the chat's own tabs were "not yours" and it opened new ones. The broker now keeps it in `~/.tether/broker-chats.json` for the same Chrome run (only chats whose Claude Code process still runs come back; a new Chrome run starts afresh).
- **Tests:** `tests/broker-profile.mjs` (a fake Chrome with two profiles: the default until the extension is seen, then your profile; remembered while the extension sleeps; an explicit profile left as asked; the chat's tabs kept across a broker restart, not across a Chrome restart), run from the unit tests; the extension end-to-end test checks the broker finds the real extension's profile by its ID; the ID formula against the one Chrome gave on Windows. 130 tests.

## 0.3.4 (2026-11-25)

The first release since 0.3.0: it also has everything in 0.3.1, 0.3.2 and 0.3.3 ([CHANGELOG.md](https://github.com/shakaibarsalan/tether/blob/main/CHANGELOG.md): the tab marker that no longer misses the extension, the broker's quick identity check, a chat working only in its own tabs, Claude's cursor that follows only Claude). After updating: reload the Tether extension (1.1.2) in `chrome://extensions` in each Chrome profile, and restart the broker (`scripts/broker-setup.ps1 -Restart` or `scripts/broker-setup.sh --restart`); Chrome asks "Allow?" once.

Found on a real Mac with the Claude desktop app (CI has none):

- **Sessions refused on a busy Mac ("check timed out", "connection not found"):** with the load average near 50, the broker's identity check found the client with `lsof` (it looks through every program's open files) and read every program's full command line with `ps`; the check ran past its 50 s, or `lsof` came back empty, and real Claude sessions were refused while sessions already let in kept working. Now the broker and its worker find the client with `netstat -anv` (one kernel query that names each socket's program; `lsof` only on a macOS without that column), retry once if nothing was found, and the broker's `check` reads only the client and its parents, without the chat's name, which is looked up after the decision, as on Windows. On this Mac: 60–190 ms under that load. The rule is unchanged: anything that isn't Claude's chrome-devtools-mcp from a signed Claude app is still refused.
- **A session let in and gone a second later:** its check had taken longer than the session's own 60 s, often the first signature check of a just-updated Claude Code. The broker now checks the running Claude Code programs' signatures every 5 minutes in the background (known ones cost nothing), and a check that takes over 5 s goes to `broker.log` with where the time went (finding the program, the check and its steps, signatures). The check's worker is started with the broker, and after a check times out its replacement starts at once, so the next session doesn't also wait for a worker to start (a time-out killed the worker and the next check started a cold one, which on an overloaded Mac timed out again).
- **"Unknown program wants Chrome: pid … path unknown" for the broker itself:** the connect watch called a connection new whenever one look missed it, and called a program unknown when it couldn't be looked up just then. A connection is now new only if it wasn't there in the last 30 s, and a program that couldn't be looked up is tried again.
- **Tests:** reading `netstat -anv` (program names with spaces, IPv6); the worker's `check` gives the same verdict as the full `verify` on a live fake session, without the name, which `session` then gives.

- **Chrome's data folder is private on newer Chrome for macOS:** every program except Chrome gets "Operation not permitted", even for `DevToolsActivePort`, so the broker never found Chrome. `scripts/port-mirror-setup.sh` builds a tiny program (`mac/port-mirror.c`) that copies only that file to `~/.tether/chrome/` every 2 seconds, runs it as a LaunchAgent, and opens Full Disk Access so you allow that one program, not node. The broker and the connect watch read the copy when Chrome's own file is private. `install.sh --broker` sets it up when it's needed; `uninstall.sh` removes it.
- **Launcher copies for more accounts:** a copy of the app such as `Claude 2.app` (started with `--user-data-dir`) was refused for its name, and a pasted Finder icon made `codesign --strict` fail. The app is now recognised by its signature: Anthropic's Developer ID and the identifier `com.anthropic.claudefordesktop`, under any bundle name starting with "Claude". A custom icon (`Icon\r` in the bundle root, FinderInfo on the bundle) is the only thing let through; anything else outside the seal, or a change inside it, is still refused.
- **`claude` not found on a Mac with only the desktop app:** the app keeps it at `claude-code/<version>/<hash>/claude.app/Contents/MacOS/claude`; `devtools-setup.sh` looks there, and in `~/ClaudeAccounts/*/claude-code` for extra accounts.
- **Chrome jumped to the front while you worked in another app:** a new tab from Claude (`new_page`) was created the default way, which focuses Chrome's window, and on a Mac that takes you out of the app you're in (Windows doesn't let apps take focus like that, so it never showed there). The same for `select_page` with `bringToFront`. Now the broker opens Claude's tabs in the background (`focus: false`), and once the tab's first page is there the extension selects it in its window (`claude-front`) while the window stays where it is. "Bring to front" goes the same way, and your own tabs are never selected. Without the extension, or on a page it can't enter (`data:`, `chrome:`), the tab is shown Chrome's way as before, and `broker.log` says so. A Chrome that doesn't know `focus` gets the tab the way it was asked. Extension 1.1.2.
- **No tab group per chat on a Mac:** the groups come from the tab-marker hook (it tells the extension which chat a tab is for), and it was only ever added by hand: on Windows it was, on the Mac it wasn't. `install.sh --broker` and `install.ps1 -Broker` now add it, and the uninstallers remove it.
- **Tests:** `tests/broker-focus.mjs` puts a fake Chrome behind the broker and checks what it sends (background tabs, shown once their page is there, never raised with the extension, Chrome's way without it, `data:` pages, the blank first page, the user's tabs, an older Chrome), run from the unit tests; the extension end-to-end test goes through the broker with the real extension (the tab starts hidden, the extension shows it, Chrome is never raised, clicks work), 32 checks; CI checks the installer adds and removes the tab marker. The Mac live test accepts "claude-script" when the tests run inside a Claude session, as on Windows.
- **Tests (port mirror and copies):** the custom-icon rule, the bundle id, launcher copies in the broker rule, the port mirror (copies privately, removes the copy, reports a missing permission) and the fallback to the copy. The live tests now run with Homebrew's node too (its `libnode` is linked next to the stand-in programs).

## 0.3.3 (2026-11-18)

- **Claude's cursor followed your mouse, fixed:** 0.3.2 took any mouse event without an input device behind it as Claude's, but in a real Chrome your own mouse moves can look the same, so moving your mouse over Claude's tab dragged Claude's cursor along. Now the broker, which forwards every mouse and key command Claude sends, posts `{ tether: 'claude-pointer', x, y, press }` (and `claude-typing`, once per burst of keys) into the page just before the input, and the extension's cursor follows only that. Your mouse and keys never move it, and your clicks are never taken as Claude's when the broker is in between. Without the broker the extension falls back to the click just before Claude's signal, as before 0.3.2. Extension 1.1.1; load it with `broker-setup.ps1 -Restart` / `broker-setup.sh --restart` and a reload of the extension in `chrome://extensions`.
- **Tests:** broker end-to-end 23 (the broker announces Claude's mouse and typing); extension end-to-end 27 (unannounced mouse input, like yours, leaves the cursor alone; it goes where the broker says). The old extension fails all three new cursor checks.

## 0.3.2 (2026-11-17)

- **Claude took over a tab you were using, fixed at the root:** when Claude closed its own tab (as it now does when a task is done) or you closed it, chrome-devtools-mcp quietly fell back to the first tab, often yours, and Claude's next step navigated it and the tab marker pulled it into Claude's group. The broker now remembers, per chat, the tabs it opened (and tabs those opened); navigating, clicking, typing into or closing any other tab is refused with a message that tells Claude to open its own, and the tab marker can't mark it. If you asked Claude to use one of your tabs, the tab guard's second `select_page` lends the chat your tabs for 30 minutes (`POST /adopt`).
- **Tab guard follows the selected tab:** it reads every chrome-devtools answer; when the selected tab is no longer one of Claude's (its tab closed and the fallback picked yours), it stops Claude until it opens or picks a tab. Its PostToolUse hook now runs on every chrome-devtools tool (re-run `tab-guard.ps1` / `tab-guard.sh`).
- **A chat stays in its Chrome profile:** a chat's new tabs open in the profile (browser context) of its first tab, instead of wherever Chrome's default is. If that profile's windows were closed, the tab opens the default way.
- **One group per chat:** a tab a chat opens in another window joins its group's window, and after a Chrome restart or when the chat comes back as a new process, its group is found again by name instead of a second one being made. Extension 1.1.0.
- **The cursor gets there before the click:** while Claude works in a tab, the cursor follows Claude's mouse live (Claude's DevTools input has no input device behind it; yours does, so your mouse is left alone), and the broker holds each click 220 ms after the mouse moved, so you see where it lands before it lands.
- **Tests:** tab guard 9; broker end-to-end 21 (kept out of a tab it didn't open, popups count as its own, the click waits, the profile sticks); extension end-to-end 24.

## 0.3.1 (2026-11-14)

- **Old marker on top of the extension, fixed:** the tab-marker hook waited 300 ms for the extension's answer. On a page still busy after loading (LinkedIn, Facebook, any big web app), Chrome can run that timer before the answer even though the answer was sent first, so the hook drew its own frame, badge and 🤖 title on top of the extension's look, and they stayed until the page changed. Now the order of window messages decides: two more messages go out behind the ping, and the extension's answer always arrives before the second one. Without the extension the hook decides in a few milliseconds instead of 300.
- **Old marker cleaned up:** when the extension answers on a page the hook once marked itself, the frame and badge are removed, and the 🤖 title prefix too (for pages marked by this version).
- **Broker: "check timed out" on a busy PC, fixed:** with the CPU at 100% and little free memory, the worker's `Get-NetTCPConnection` took 4 to 13 s (more in a freshly started PowerShell), each timeout killed the worker, and the next check started cold and timed out again: real Claude sessions were refused for 40 minutes. The worker now finds the process with `netstat` (0.1 s), and the broker passes the pid it already has (`check <port> <pid>`), so the worker only walks the process's parents (under a second warm, about 3 s cold). The chat's name is looked up after the decision, on a second worker that also runs the signature checks and notifications, so "who is this?" never waits behind them. The log line still names the chat. macOS: the same `check` request.
- **`broker-setup.ps1 -Restart` / `broker-setup.sh --restart`:** load a broker update. `Stop-ScheduledTask` alone left the old broker running ("port 9333 is busy").
- **Extension 1.0.1, one group per chat even when two tabs speak at once:** the service worker now handles one message at a time. Two tabs of the same session signalling together both found no group yet and the chat got two groups with the same name. Reload the extension in `chrome://extensions` to pick it up.
- **Tests:** the extension end-to-end test checks a busy page, the clean-up, that the fallback is quick, and two tabs of one session signalling at the same moment; it closes the busy page before the group checks and gives a slow machine up to 5 s to group the tabs. On Windows the broker's worker answers `verify` and `check` on real connections, and the whole broker refuses a plain program quickly. 118 tests. Re-run `scripts/tab-marker.ps1` (or `tab-marker.sh`) to put the new hook in `settings.json`.

## 0.3.0 (2026-11-13)

- **macOS:** everything Tether does on Windows now works on a Mac. `./install.sh [--broker]` and `./uninstall.sh`; `scripts/bridge-block.sh` (`/etc/hosts`, asks for your password once, flushes the DNS cache) with `Block-Remote.command` and `Unblock-Remote.command` to double-click; `scripts/devtools-setup.sh` (chrome-devtools-mcp pinned in `~/.tether/npm`, no sudo); the broker and the connect watch as LaunchAgents (`broker-setup.sh`, `connect-watch-setup.sh`, each with `--status` and `--undo`); `scripts/check.sh` (`--hook`, and `--install-hook` to run it at every session start); `tab-marker.sh`, `tab-guard.sh`, `guard-install.sh` and `guard-uninstall.sh`. Every PowerShell command has a twin; [docs/macos.md](docs/macos.md) lists them.
- **Broker on macOS:** `scripts/connect-watch.mjs --serve` answers its checks. `lsof` and `ps` find who connected; Claude Code and `Claude.app` must both pass `codesign --verify --strict` and be signed with Anthropic's Developer ID ("Developer ID Application: Anthropic PBC", team id matching, chained to Apple's root). Windows is unchanged.
- **Releases:** pushing a `v*` tag runs every test on Windows and macOS, then publishes `tether-<version>-windows.zip`, `tether-<version>-macos.tar.gz`, the extension zip and `SHA256SUMS.txt`, with the notes from this file.
- **CI:** `macos-latest` runs the unit tests, the broker and extension end-to-end tests against a throwaway Chrome, and a full `./install.sh --broker`, check and `./uninstall.sh` on a fresh Mac.
- **Tests:** 115 (20 of them macOS only).

- **Tab guard:** `hooks/tab-guard.mjs` (installed by `scripts/tab-guard.ps1`) stops Claude from acting in the tab you're using: it must open its own tab or pick one first, and a tab it didn't open is refused once. A session had taken over a Gmail tab the user was working in.
- **One tab group per session, named after the chat:** the broker fills the tab-marker hook's `__TETHER_SESSION__` placeholder with the client's session id and title (looked up again every 30 s, since new sessions get a title later); the extension keeps a group per session per window and renames it when the title arrives.
- **Broker checks:** a long-lived PowerShell worker (`connect-watch.ps1 -Serve`) answers in about a second instead of a new PowerShell per check, which on a full disk timed out and refused real sessions; reconnecting processes that were already let in skip the check (pid via netstat).
- **Notifications off by default:** turn them on with `{ "notifications": true }` in `%USERPROFILE%\.tether\config.json`.

- **Broker:** `broker/tether-broker.mjs` holds one DevTools connection to Chrome, so Chrome asks **Allow?** once per Chrome start instead of once per Claude Code session. Sessions connect to it on `ws://127.0.0.1:9333` and get in only if they are chrome-devtools-mcp started by a Claude desktop session whose `claude.exe` and app are both validly signed by Anthropic, PBC; everything else gets 403 and a notification. Each session gets its own browser session (`Target.attachToBrowserTarget`); `Browser.close`, `Browser.crash` and `Target.exposeDevToolsProtocol` are refused; requests with an Origin or a foreign Host are refused. One dependency, `ws`, pinned. `scripts/broker-setup.ps1` installs it as a login task and points Claude Code at it (`-Status`, `-Undo`); `install.ps1 -Broker` includes it.
- **Connect watch:** names the broker ("Tether wants Chrome"), shows the broker's decisions, answers its `-VerifyClientPort` checks, and finds the title of brand-new sessions (no id on the command line) by start time.
- **Check script:** recognises the broker as a known client.
- **DevTools setup:** `-Broker` registers chrome-devtools-mcp with `--wsEndpoint` to the broker; skips `npm install` when the pinned version is already there.
- **Extension:** Claude's cursor style: a slim tilted arrow with a **Claude** tag that rings on a click and settles after a moment; a richer edge glow; a cream status pill.
- **Tests:** 69, plus `tests/broker-e2e.mjs`.
- **Chrome Web Store package:** the extension is 1.0.0. `store/` holds the listing text with permission justifications and reviewer steps (`listing.md`), three 1280×800 screenshots and the 440×280 promo tile (made by `store/make-assets.mjs` with the real extension), and `store/build-zip.ps1`, which builds `dist/tether-<version>.zip`. Privacy policy: `docs/privacy.md`.

- **Connect watch:** `scripts/connect-watch.ps1` pops up a Windows notification the moment a program connects to Chrome's debugging port, which is when Chrome shows **Allow?**. It names the Claude Code session behind chrome-devtools-mcp (its title, folder and account folder), flags scripts a session ran itself, and keeps a notification on screen for anything else. Every connection is logged to `%USERPROFILE%\.tether\connect-watch.log`. `scripts/connect-watch-setup.ps1` runs it at every login with no window (Task Scheduler, no admin), with `-Status` and `-Undo`. `install.ps1` and `uninstall.ps1` include it.
- **Chrome extension:** `extension/` shows which tabs Claude Code is using: an orange **Claude** tab group, an hourglass tab icon that turns into a green ✓ when Claude stops, a breathing orange edge glow, a status pill and an orange cursor that glides to Claude's clicks and typing. Display only: two permissions (`tabGroups`, `storage`), no network, no debugger, top frame only.
- **Tab-marker hook:** now asks the extension first (`postMessage`, 0.3 s wait for an ack) and falls back to the in-page marker without it. Re-run `scripts\tab-marker.ps1` to update an installed hook.
- **Tests:** 61, plus `tests/extension-e2e.mjs`, which loads the extension in a throwaway Chrome and acts like Claude Code.

## 0.2.0 (2026-11-09)

- **Check script:** `scripts/check.ps1` verifies the hosts block, that Chrome was restarted after it, that remote debugging is loopback-only, and whether Remote Control is off. It also scans every installed Claude in Chrome version for remote hosts it hasn't seen, and caches what it scanned. `-Hook` makes it a quiet `SessionStart` hook that only speaks up when something changes.
- **Tab marker:** `scripts/tab-marker.ps1` adds a hook that marks the tab Claude Code is driving: 🤖 in front of the title, an orange frame and a badge. It never blocks clicks. `-Undo` removes it.
- **Who's connected:** `check.ps1` names every program attached to Chrome's debugging port and what started it, and flags anything that isn't Claude's chrome-devtools-mcp.
- **DevTools setup:** the server is registered with `--no-page-id-routing`, so hooks can act on the tab Claude last used.
- **Guide video:** 25 seconds, with a Kokoro voice-over, subtitles and four quiet sounds. `video/voiceover.py` builds the audio and timeline.
- **Docs:** README explains how to run the check at session start and why to disable Remote Control on shared accounts. The guide video now plays at the top of the README.
- **Tests:** 47.

## 0.1.0 (2026-11-08)

First release.

- **Bridge block:** `scripts/bridge-block.ps1` with `-Undo` and `-Status`, plus `Block-Remote.bat` and `Unblock-Remote.bat`. Backs up the hosts file every run, and re-runs are safe.
- **Local control:** `scripts/devtools-setup.ps1` pins chrome-devtools-mcp 1.12.0 and registers it with `--autoConnect`.
- **One-step install:** `install.ps1` and `uninstall.ps1`.
- **Guard hook:** Python and Windows PowerShell versions, with an installer that backs up `settings.json`, replaces only its own entries and self-tests.
- **Fix:** the guard reads hook input as raw UTF-8, so Urdu and other non-English text is no longer blocked.
- **Tests:** 38 tests, and CI on `windows-latest`.
